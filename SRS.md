# Word Forge Software Requirements Specification

**Version:** 0.1  
**Status:** Approved for initial design and implementation  
**Product:** Word Forge  
**Target platform:** DeepSpace SDK

## 1. Purpose

Word Forge is a structured prewriting workspace for fiction. It helps a writer build a story from the bottom up by defining its world, characters, plot, timeline, and chapter plans before generating prose.

Unlike prompt-to-story generators, Word Forge treats story information as a connected body of canon. Human writing and AI suggestions remain distinguishable, AI suggestions require explicit approval, and chapters can be flagged when the canon they depend on changes.

## 2. Product Goals

1. Help a writer turn an early premise into sufficiently detailed prewriting material.
2. Make gaps in the world, characters, and plot visible without forcing a rigid workflow.
3. Let AI propose targeted content using only the currently relevant context.
4. Keep the writer in control of what becomes canon.
5. Track which canon elements influence each chapter and identify potentially stale writing.
6. Demonstrate meaningful use of DeepSpace authentication, records, realtime synchronization, AI, and file storage.

## 3. Non-Goals for V1

The submission version will not include:

- AI-generated images.
- A geographical map or grid editor.
- A visual node graph for relationships.
- Drag-and-drop custom card groups.
- A graphical timeline editor.
- Full manuscript export or publishing.
- Automatic continuity rewriting.
- Rich-text collaboration or multiplayer cursors.
- Arbitrary user-authored genre template builders.
- Payments, scheduled jobs, or messaging.

## 4. Users and Roles

### 4.1 Writer

An authenticated user who creates and manages their own story projects.

The writer can create projects, edit elements, request AI suggestions, accept or reject suggestions, attach images, add stage-level text references, preview or remove those references, generate chapter drafts, and resolve consistency warnings.

### 4.2 Co-author

Post-V1 role. A project owner may invite another authenticated user to edit a shared project. The data model should not prevent later collaborator support, but invitation UI is outside the initial submission scope.

## 5. Core Concepts

### 5.1 Project

A project represents one story and contains its overview, world elements, characters, plot points, and chapters.

### 5.2 Element

An element is a structured unit of prewriting information, such as a character, location, religion, technology, species, faction, or plot point.

Each element contains a title, short preview, typed fields, canon state, provenance information, attachments, and optional links to other elements.

### 5.3 Canon State

Every element is either:

- **Canon:** Approved information that AI may treat as true when generating later material.
- **Sketch:** An exploratory idea that must not influence generation unless explicitly selected by the writer.

### 5.4 Provenance

Each editable field records one of the following origins:

- `human`: Written by the writer.
- `ai_pending`: Proposed by AI but not approved.
- `ai_accepted`: Generated by AI and explicitly accepted.
- `human_edited_ai`: Originally generated by AI and later edited by the writer.

The interface must not rely on color alone. Provenance is communicated through a subtle field background and a text or icon badge. Element cards use neutral borders; provenance must not be represented by a colored left edge or accent stripe.

### 5.5 Suggestion

An AI suggestion is a proposed change associated with one element and one field. Suggestions remain separate from canonical content until accepted.

### 5.6 Coverage

Coverage is the percentage of relevant template fields containing accepted, canonical content. It measures how much of the prewriting structure has been addressed, not writing quality.

Pending AI suggestions and sketch-only content do not count toward coverage.

### 5.7 Dependency

A chapter may reference characters, world elements, and plot points. Word Forge records those references and the last-reviewed version of each referenced element.

When a referenced canonical element changes after the chapter was generated or reviewed, the chapter becomes `Needs review`.

## 6. V1 User Experience

### 6.1 Project Dashboard

The authenticated home screen displays existing projects and an action to create a project.

Creating a project requires:

- Project title.
- Premise.
- Genre template: Fantasy, Science Fiction, or Contemporary.
- Overview begins with the title, genre, and overview description. Once those are present, the later overview layer reveals tone and optional lessons or morals.
- Chapters owns the editable Voice & Tone profile: emotional voice, pacing, description style, dialogue style, point of view, and inspiration notes.
- Optional lessons or morals the writer wants the story to explore or convey.

The selected genre determines the initial recommended worldbuilding cards.

### 6.2 Workspace Navigation

The project workspace contains the following tabs:

1. Overview
2. World
3. Characters
4. Plot
5. Chapters

The current project title and Story Completion remain visible in the workspace header. A compact AI assistant launcher remains available in the lower corner.

Tabs follow a gated prewriting sequence:

1. Overview is available when a project is created.
2. World unlocks after Overview is complete.
3. Characters and Plot unlock together after World is complete, allowing either a character-driven or plot-driven workflow.
4. Chapters unlock after both Characters and Plot are complete.

Within an unlocked stage, later elements stay visually hidden until the stage's setup gate is satisfied. Plot requires a duration before plot cards appear. Characters requires at least one protagonist and one antagonist role before character cards appear. Overview reveals its lessons and morals layer after the core description is complete. These are progressive-disclosure gates inside a stage and do not change the five-stage completion model.

A stage is complete when its required template fields contain accepted Canon content and the writer explicitly selects `Complete stage`. Sketch content and pending AI suggestions do not satisfy a requirement. Unlocking is permanent; later edits may mark an earlier stage `Needs attention`, but they do not re-lock downstream tabs.

### 6.3 Card and Detail Pattern

World, Characters, and Plot display their elements as compact cards.

Each card shows:

- Element title.
- Type.
- Canon or Sketch badge.
- Short AI-generated or manually written overview.
- Field coverage.
- Consistency warning, when applicable.

Selecting any part of a card opens a focused detail editor with a back arrow. The writer can immediately place the cursor in a field and type; AI interaction is optional and must never be required to edit an element. Human typing updates the field directly, records human provenance, and autosaves.

The detail editor displays all fields, provenance, attachments, relationships, and optional field-level AI actions. Cards and editor fields use neutral container borders. Provenance appears inside the content area through labels and subtle backgrounds, never as a colored left border.

### 6.4 Genre Templates

Templates provide recommended element types and fields. Writers may add, rename, or remove individual elements.

#### Fantasy

- Magic system.
- Religions and beliefs.
- Cultures and factions.
- Species.
- Notable locations.
- Historical events.

#### Science Fiction

- Technologies.
- Scientific constraints.
- Species.
- Planets and locations.
- Governments and factions.
- Historical events.

#### Contemporary

- Locations.
- Institutions.
- Communities and social context.
- Relevant history.
- Real-world constraints.

### 6.5 Character Template

Character elements support:

- Name.
- Story role.
- Motivation.
- Goal.
- Strengths.
- Weaknesses.
- Background.
- Skills.
- Internal conflict.
- Relationships.
- Appearance notes.
- Reference images.

### 6.6 Plot and Timeline

V1 represents plot points as an ordered list. Each plot point supports:

- Title.
- Description.
- Narrative purpose.
- Characters involved.
- World elements involved.
- Cause.
- Consequence.
- Order.

The Plot stage also includes a project timeline span slider. Its logarithmic range runs from one day to one century and displays the nearest practical unit: days, months, years, or centuries.

### 6.7 Tropes

Overview exposes the full genre-aware trope library, while World, Characters, and Plot show a random subset as starter prompts until the writer begins entering content in that section. Clicking a trope creates a Sketch card. Tropes may include follow-up card ideas for later sections; those are stored as pending suggestions and never become canon automatically.

### 6.8 Chapters

Each chapter supports:

- Title and order.
- Chapter objective.
- Synopsis.
- Draft body in plain text.
- Linked characters, world elements, and plot points.
- Generation timestamp.
- Last reviewed timestamp.
- Consistency status.

The writer may create and edit chapter drafts after the Chapters stage unlocks. Chapter generation remains unavailable until Overview, World, Characters, and Plot have each been explicitly completed at least once.

## 7. Functional Requirements

### 7.1 Authentication and Projects

- **FR-001:** Word Forge shall require authentication before project data is shown.
- **FR-002:** A writer shall be able to create, rename, open, and delete their own project.
- **FR-003:** A writer shall not be able to read or modify another writer's private projects.
- **FR-004:** Project changes shall persist through DeepSpace records.

### 7.2 Elements

- **FR-010:** A writer shall be able to create, edit, and delete elements.
- **FR-011:** Each element shall belong to exactly one project and one primary section.
- **FR-012:** Each element shall support Canon and Sketch states.
- **FR-013:** Element cards shall show a brief preview without requiring the detail view.
- **FR-014:** Selecting an element shall open a full detail view with a back action.
- **FR-015:** A writer shall be able to add a custom element even when it is not part of the selected genre template.
- **FR-016:** Element changes shall update connected clients through DeepSpace realtime records.
- **FR-017:** A writer shall be able to type directly into any editable field immediately after opening an element.
- **FR-018:** Human field edits shall autosave and record human provenance without passing through the AI suggestion workflow.
- **FR-019:** Element cards and fields shall not use colored left borders or accent stripes to indicate provenance.

### 7.3 Coverage and Guidance

- **FR-020:** Word Forge shall calculate Story Completion from five equal stage buckets: Overview, World, Characters, Plot, and Chapters.
- **FR-021:** An element card or chapter shall count as complete when its writing fields or authored/AI-proposed summary contains any non-empty content; template summaries are guidance and do not count. Cards shall not display a fractional completion level.
- **FR-022:** An untouched or locked stage shall contribute `0%` to Story Completion, even when starter records exist for it.
- **FR-023:** Each element stage shall divide its bucket evenly across its cards, and Chapters shall divide its bucket evenly across its chapters.
- **FR-024:** Overview shall be the only editable stage when a project is first created.
- **FR-025:** World shall unlock when required Overview fields are filled and the writer completes the Overview stage.
- **FR-026:** Characters and Plot shall unlock together when every World card contains some content and the writer completes the World stage.
- **FR-027:** Chapters shall unlock when every Character and Plot card contains some content and the writer completes both stages.
- **FR-028:** Locked tabs shall remain visible and shall identify the prerequisite needed to unlock them.
- **FR-029:** Characters and Plot shall remain a paired gate for Chapters; Chapters shall not remain unlocked when either section no longer has content in every card.
- **FR-030:** Overview shall reveal its lessons and morals layer only after title, genre, and overview description are present.
- **FR-031:** Plot shall reveal plot elements only after a project timeline duration is selected.
- **FR-032:** Characters shall reveal character elements only after at least one protagonist and one antagonist role are assigned; custom role labels containing those terms qualify.
- **FR-033:** Chapters shall contain the editable Voice & Tone writing settings rather than Overview.

### 7.4 AI Assistant

- **FR-030:** The AI assistant shall receive the current project overview and selected tab.
- **FR-031:** When an element is selected, the assistant shall receive that element, its template, and directly linked canonical elements.
- **FR-032:** The assistant shall not receive unrelated project content during an element-level request.
- **FR-033:** Chapter generation may receive the project overview plus only the elements explicitly linked to that chapter.
- **FR-034:** AI output intended for a field shall create a pending suggestion and shall not directly overwrite canonical content.
- **FR-035:** The assistant shall be able to explain, brainstorm, or propose a field update from the corner chat.
- **FR-036:** An assistant response that can update a field shall expose an `Apply to field` action.

### 7.5 Suggestion Review

- **FR-040:** Selecting AI-proposed text shall open a suggestion popup.
- **FR-041:** The popup shall display Reject, Accept, and Revise actions using an X icon, check icon, and refresh icon respectively.
- **FR-042:** The Accept action shall copy the suggestion into the target field and set its provenance to `ai_accepted`.
- **FR-043:** The Reject action shall mark the suggestion rejected and remove it from the active field view.
- **FR-044:** The revision input shall use the placeholder `Enter a revision...`.
- **FR-045:** The refresh action shall remain disabled until revision instructions contain non-whitespace text.
- **FR-046:** Pressing Enter in the revision input shall request regeneration. Shift+Enter shall insert a new line.
- **FR-047:** During regeneration, the current suggestion shall remain visible, become more muted, and be non-interactive.
- **FR-048:** During regeneration, review controls shall be disabled and a progress indicator shall be visible.
- **FR-049:** A successful revision shall replace the visible suggestion with the new pending version.
- **FR-050:** A failed revision shall restore the prior suggestion and preserve the writer's revision instructions.
- **FR-051:** Previous suggestion versions shall remain stored for provenance even when not exposed in the V1 interface.

### 7.6 Images and Attachments

- **FR-060:** A writer shall be able to attach an image to an element.
- **FR-061:** Image bytes shall be stored using DeepSpace file storage.
- **FR-062:** Attachment metadata shall be stored in a project-owned record.
- **FR-063:** V1 shall display attachments adjacent to element text rather than embedding them inside rich text.
- **FR-064:** The interface shall show upload progress and failure states.

### 7.7 Stage References

- **FR-065:** A writer shall be able to attach a private `.txt` or `.md` reference file to Overview, World, Characters, Plot, or Chapters.
- **FR-066:** Stage reference files shall be listed with their filename, size, and status and shall be readable in a read-only preview modal.
- **FR-067:** A writer shall be able to remove a stage reference after confirmation, deleting both its metadata record and stored file.

### 7.8 Chapters and Consistency

- **FR-070:** A writer shall be able to create and edit chapter records.
- **FR-071:** A writer shall be able to select which canonical elements a chapter uses.
- **FR-072:** AI chapter generation shall use only the selected canonical elements and project overview.
- **FR-073:** Word Forge shall store a dependency snapshot when a chapter is generated or marked reviewed.
- **FR-074:** A chapter shall become `Needs review` when any linked canonical element has changed since the dependency snapshot.
- **FR-075:** The chapter detail view shall identify which linked elements changed.
- **FR-076:** A writer shall be able to mark a chapter reviewed after resolving inconsistencies.

## 8. Suggestion State Model

Valid suggestion states are:

- `pending`
- `regenerating`
- `accepted`
- `rejected`
- `failed`
- `superseded`

Valid transitions are:

- `pending -> accepted`
- `pending -> rejected`
- `pending -> regenerating`
- `regenerating -> superseded`, when a replacement succeeds
- `regenerating -> failed`, when regeneration fails
- `failed -> pending`, when the previous suggestion is restored

The previous suggestion must not be discarded before its replacement has persisted successfully.

## 10. DeepSpace Integration Requirements

### 10.1 Authentication and Permissions

DeepSpace authentication shall protect all application routes. Record schemas shall enforce per-user ownership on the worker, not only through client filtering.

### 10.2 Realtime Records

Projects, elements, suggestions, chapters, and attachment metadata shall use DeepSpace collections and realtime query hooks.

### 10.3 AI Chat and Server Actions

The contextual assistant shall use DeepSpace AI chat. Custom tools or server actions shall create suggestion records and generate chapters using an authenticated caller's permitted records.

### 10.4 File Storage

Reference images shall use the DeepSpace R2 file API. Word Forge must be deployed once before end-to-end local upload testing because local file credentials are provisioned after the first deployment.

### 10.5 Optional Collaboration

If time permits, projects may use a collaborators field and DeepSpace shared permissions. This is not required for the submission's core path.

## 11. Non-Functional Requirements

- **NFR-001:** The primary experience shall be optimized for desktop widths of 1024 pixels and above.
- **NFR-002:** Essential project navigation and reading shall remain usable on mobile, even if dense editing is desktop-first.
- **NFR-003:** Buttons shall have accessible names and unfamiliar icon controls shall have tooltips.
- **NFR-004:** Provenance shall never be communicated by color alone.
- **NFR-005:** Destructive actions shall require confirmation or provide a recoverable soft-delete path where practical.
- **NFR-006:** AI and network operations shall expose loading, success, and recoverable error states.
- **NFR-007:** Secrets and credentials shall not be committed to the repository.
- **NFR-008:** AI shall not receive Sketch elements unless the writer explicitly selects them.
- **NFR-009:** The important path shall have an automated browser test and a manual two-session verification.

## 12. Acceptance Scenarios

### AS-001: Build Canon from a Template

Given an authenticated writer creates a Fantasy project, when the project opens, then Word Forge displays Fantasy-specific worldbuilding cards and an initial coverage score.

### AS-001A: Unlock Prewriting Stages

Given a new project with a completed Overview, when the writer explicitly completes the Overview stage, then World unlocks while Characters, Plot, and Chapters remain locked. When World is completed, Characters and Plot unlock together. Chapters unlock only after both are completed.

### AS-001B: Edit a Card Directly

Given an unlocked section, when the writer opens an element card and types in a field, then the text autosaves as human-authored content without creating an AI suggestion.

### AS-002: Review an AI Suggestion

Given the writer requests a character motivation, when the assistant responds, then the proposed motivation is visibly pending and does not count toward coverage until accepted.

### AS-003: Revise a Suggestion

Given a pending suggestion and non-empty revision instructions, when the writer activates refresh, then the old text becomes muted until a new pending version replaces it. If the request fails, the original returns to its active state.

### AS-004: Protect Sketch Ideas

Given an element marked Sketch, when the writer generates a chapter without explicitly selecting that element, then its content is absent from the generation context.

### AS-005: Detect Stale Writing

Given a chapter linked to a canonical character, when that character changes after chapter generation, then the chapter shows `Needs review` and identifies the changed character.

### AS-006: Persist an Image

Given a signed-in writer uploads a supported image, when the upload succeeds, then the image appears on the element and remains available after a page reload.

## 14. Primary Tradeoff

Word Forge prioritizes a complete canon-to-chapter workflow over broad authoring features. V1 uses gated prewriting stages, directly editable structured cards, plain-text chapter editing, and ordered plot points so that provenance, AI approval, context selection, and consistency warnings can be finished and verified within the submission window.
